# Каби-бункер: handoff

Браузерный клон «Бункера» для игры с друзьями. Интерфейс на русском. Это не официальный сайт bunker-online.com: визуальную структуру повторять можно, а исходный код, закрытые ресурсы и фирменные материалы оригинала копировать нельзя.

- **GitHub:** https://github.com/Original120005/kabi-bunker (ветка `main`). Последний коммит на 08.11.2026: `c396de4`.
- **Node 22, npm workspaces, TypeScript.** В PowerShell нет `&&`, команды разделяются `;`.

## Запуск

- `npm run play` собирает клиент, поднимает игру на http://localhost:3000 и открывает Cloudflare Quick Tunnel. Ссылка `https://….trycloudflare.com` меняется при каждом запуске, друзья заходят по ней. Остановка — Ctrl+C.
- `npm run play:lan` даёт адрес в локальной сети без туннеля.
- После каждого запуска новый callback `https://….trycloudflare.com/api/auth/discord/callback` нужно добавить в Discord OAuth2 Redirects. `http://localhost:3000/api/auth/discord/callback` остаётся там постоянно.
- **Боты:** `node scripts/bots.mjs КОД 9 http://localhost:3000`. Если число не сказано, запускать 9. Запускать в отдельном окне PowerShell. Перед новым запуском закрыть старые процессы `bots.mjs`. Процесс `npm run play` на порту 3000 не убивать. Секрет бота берётся из `BOT_SECRET`, не печатать его.

## Стек и архитектура

- **Сервер:** Fastify + Socket.IO + Prisma + SQLite (`data/bunker.db`). Состояние комнаты пишется в SQLite. После перезапуска комната восстанавливается, но адрес туннеля новый.
- **Клиент:** React 18, Vite, Tailwind 4, Zustand.
- **Общие схемы:** Zod в `packages/shared`.
- **Игровая логика:** чистые функции в `packages/engine` (`applyAction`, `advanceRoom`, свой ГСЧ mulberry32 в `rng.ts`).
- **Секретность:** клиент не получает закрытые карты, в проекции чужая закрытая карта — только `{ charKey, hidden: true }`. Случайность, голоса, таймеры и вердикты считает только сервер. Отложенные этапы (вылазка, рулетка ивента, вердикт итогов) сервер раскрывает по своим часам через `nextWakeAt` / `advanceRoom` в `packages/engine/src/raid.ts`.
- **Устаревшие документы:** README.md и `docs/architecture/ARCHITECTURE.md` частично устарели. Там написано, что голосования и панели ведущего нет, и нарисована другая структура папок. Верить коду, а не этим документам.
- **Вход:** только через Discord. В `.env` лежат `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET` и `BOT_SECRET`. Секреты нигде не печатать и не пересказывать. Cookie сессии — `bunker_sid`.

## Контент

- Лежит в `content/packs/base/`: `definitions.json` и `items/*.json`.
- `npm run seed` переносит его в базу и не перезаписывает уже существующие строки. Правки весов, текстов, ссылок, `enabled`, `data.effect` и `definitions.json` попадают в базу только через `npm run seed:update`. Это нужно один раз после правки JSON, а не перед каждым запуском. `npm run play` вызывает обычный seed.
- Сервер читает контент в память при старте. Поэтому после правки JSON и сида нужны перезапуск `npm run play` и новая партия.
- Удалённая из JSON строка из базы сама не исчезает. Её надо оставить с `"enabled": false` и прогнать `seed:update`.

## Правила игры

- **Игроки и места:** от 6 до 15 игроков. Мест в бункере — половина, округление вниз.
- **Карты персонажа:** пол и возраст (16–85, 10% «ч/ф»), телосложение и рост, черта, профессия со стажем, здоровье, хобби, фобия, крупный инвентарь, рюкзак, дополнительное сведение, две спецкарты.
- **Бункер:** размер, срок, еда, история, локация, комнаты, три предмета. Плюс катастрофа.
- Внутри одной партии значения не повторяются, пока пул не кончится.
- Ведущий почти всё делает руками с панели (`apps/web/src/host/HostPanel.tsx`). Голосование запускает ведущий.
- **Отмена действий:** лимит 10. Отмена не откатывает генератор случайных чисел, поэтому повтор действия даёт новый результат.

### Рост и телосложение

- Рост выпадает по нормальному распределению в пределах 150–210. Настройка — `normal` в `definitions.json`: мужчины 178±7, женщины 165±6.5.
- В панели есть раздел «Изменить телосложение» (тип или «Случайно»). Он меняет только тип, рост сохраняется. «Изменить характеристику → Телосложение» перегенерирует карту вместе с ростом.

### Здоровье

- Отдельный бросок: 30% «Идеально здоров» (тег `health:none`, без степени), это значение может выпасть нескольким игрокам. Остальные 70% — равномерно среди болезней, без учёта `weight`.
- Жёсткие болезни (Covid-19, ВИЧ, гепатит B, рак, туберкулёз, гемофилия, синдром хрустального человека, диабет 1-го типа) могут быть любой степени, включая критическую.
- Наведение на болезнь показывает короткое описание и ссылку «Открыть в Википедии». Ссылка лежит в `data.link` и доходит до карты через `makeCard` и проекцию.
- Тултип живёт в `apps/web/src/game/Hint.tsx`. Его можно нажать, и он не должен ломать подсказки профессий.

### Срок бункера

Каждый месяц от 1 года до 6 лет, например «2 года 3 месяца». «6 месяцев» и «8 лет» выключены. Сроки еды и истории не трогать.

### Вылазка

- Базовый шанс вернуться живым — 60%. К нему прибавляются тело, возраст и только первая карта здоровья. «Идеально здоров» +10, тяжёлая степень −5, критическая −10, лёгкая и средняя на шанс не влияют.
- Средний шанс случайного персонажа около 56%. Проверено симуляцией: рулетка честная, колесо останавливается на выпавшем значении.
- **Лут:** первая находка гарантирована и берётся из тира 3 (Редкое). Дальше шансы 70%, 50%, 50%, 50% на тиры 2, 3, 4, 5. Первый промах останавливает поиск.
- Рулетка игроков и предметов общая: длина ленты 44, победная ячейка 38.

### Ивенты

- Кнопка ведущего «Запустить ивент». Пул в `packages/engine/src/events.ts`, около 63 событий, без повтора, пока список не кончится. Картинки — `apps/web/public/images/events/{key}.jpg`.
- Объявление лежит вне партии, отмена хода его не убирает. Проблемы бункера остаются текстом.
- Если событие бьёт по одному человеку, крутится та же рулетка, что на вылазке. В ней только живые в лагере, без того, кто сейчас на вылазке (стадии `picking`, `away`, `returning`). Болезнь добавляется второй строкой. Находка кладётся в рюкзак и сразу открыта. Карта записывается только когда лента остановилась.
- Пока рулетка ивента крутится, новый ивент, старт вылазки и подведение итогов запрещены.
- Запущенные за партию ивенты пишутся в `state.partyEvents` (сбрасывается при старте и рестарте) и учитываются в итогах.
- Файл `ивенты-и-вылазка.txt` на рабочем столе — список ивентов и лута по кругам. Если меняются тексты ивентов, его стоит обновить.

### Спецкарты и способности профессий

- Эффект хранится в `data.effect` элемента контента. Схема — `SpecialEffect` / `SimpleEffect` в `packages/shared/src/content.ts`. Операции: `give`, `add`, `remove`, `steal`, `swap`, `swap.pair`, `reroll`, `modifier.step`, `modifier.set`, `healthy`, `curePhobia`, `childfree`, `gender.flip`, `ageGroup`, `body`, `bunker.reroll`, `bunker.set`, `bunker.addItem`, `catastrophe.reroll`, `seats`, `rotate`, `nullify`, `return`, `reveal`, `cancelSpecial`, `manual`, `info`. Составные — `choice` («или») и `multi` («и»). Цели: `self`, `other`, `any`, `all`, `neighbor`, `neighbors`. `note` — подсказка ведущему.
- Применяет всё одно действие `host.special.apply`, логика в `applySpecial` / `applySimple` в `packages/engine/src/host.ts`. Окно — `apps/web/src/host/ApplySpecial.tsx`.
- **Профессии:** у всех 318 прописан эффект. Ведущий видит кнопку «⚡ способность» под открытой профессией в таблице игроков (`PlayersTable.tsx`). Профессия должна быть открыта. Способность используется один раз, и отметка «использовано» переходит вместе с картой. Учёный получает чужую профессию неиспользованной. Категорию болезни у узких врачей проверяет ведущий, код проверяет только степень. Речь, голоса, связи между бункерами и проблемы бункера отмечаются вручную с подсказкой. Постоянные свойства (`info`) кнопки не имеют.
- «Отменить спец. возможность» (спецкарта, Лоббист, Каскадёр, Священник) отменяет только спецкарты, а не способности профессий.
- Строка, добавленная в рюкзак или инвентарь, сразу открыта, если эта характеристика у игрока уже открыта.
- Если у игрока две строки здоровья, снижение степени меняет те строки, которые можно, а лечение убирает одну болезнь. Строку ведущий может выбрать в окне.

### Итоги партии

- Кнопка «Подвести итоги партии» доступна, только если живых в лагере не больше, чем мест. Все живые становятся «в бункере».
- Сервер симулирует выживание бункера. Расчёт — `packages/engine/src/finale.ts`, правила, веса и таблицы — `packages/shared/src/finale.ts`. Шанс = 58 + сумма факторов, в пределах 5–95.
- **Факторы:**
  - продолжение рода: женщина 16–50 лет, не ч/ф, не «Хрупкое» и не «Ожирение-сильное», плюс мужчина не ч/ф;
  - возраст и здоровье, отдельно заразные болезни без медика;
  - навыки профессий (медицина, техника, еда, защита, моральный дух) и опыт;
  - снаряжение (ключевые слова в рюкзаках, инвентаре и предметах бункера);
  - еда против срока, своё пропитание, площадь на человека;
  - поломки из истории бункера;
  - требование катастрофы;
  - хорошие и плохие ивенты партии;
  - один финальный ивент.
- Случайный состав выживает примерно в 50% случаев.
- **Показ всем** (`apps/web/src/game/FinalePopup.tsx`): факторы по очереди (▲/▼, сила 1–3, без чисел), финальный ивент, шанс словами, вердикт и таблица рейтинга. Вердикт и рейтинг сервер отдаёт только после `revealAt`.
- **Рейтинг пишется один раз:** прошедший в бункер +20 и ещё +10, если бункер выжил. Первый изгнанный −20, второй −10, остальные 0. Боты в рейтинг не попадают. Итог окончательный.
