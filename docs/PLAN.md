9. `npm run play`: сборка клиента, запуск сервера, резервная копия БД, туннель Cloudflare и вывод ссылки; режим `--lan`. Инструкция `docs/HOW_TO_PLAY.md` для заказчика.

## Этап 4. Игровые механики

1. Фазы раунда и порядок ходов (чередование направлений).
2. Серверные таймеры и панель таймера ведущего (15/30/60, пауза, стоп, горячие клавиши 1–6).
3. Раскрытие по таблице, обязательная профессия, закрытие случайно открытой карты.
4. Голосование по полному алгоритму: 70%, ничьи, оправдания один раз за раунд, переголосования, пропуск в 1-м раунде, двойное голосование, голос против себя за неучастие, прощальные речи, план исключений.
5. Панель ведущего: все 14 групп из `research/04-host-panel.md`, изгнать/вернуть, места ±, смена катастрофы, отмена последнего действия, перезапуск, смена ведущего, сообщения игрокам, кубики d6/d20.
6. Реестр эффектов и применение способностей: заявка «Стоп игра», исполнение ведущим (автоматическое или ручное), карты отмены, лимиты, тайминги, запреты по фазам.
7. События: лёгкие и сложные, ручной ввод, квест «Успех/Провал», лимиты 2+1, предложение события игроком.
8. Финал: раскрытие у прошедших, проверка «прошедших не больше мест», итоги, тест выживаемости.

## Этап 5. Контент

1. Базовые характеристики, шкалы и модификаторы по оригиналу.
2. 318 профессий оригинала со структурированными эффектами, где это возможно; остальные с типом `narrative`.
3. Авторские спец. карты: реконструкция по примитивам панели ведущего и пяти группам карт из Wiki.
4. Авторские катастрофы и поля бункера, включая проблемы бункера с тегами.
5. Для здоровья, хобби, фобий, черт, инвентаря, рюкзака и доп. сведений — примеры из Wiki оригинала и готовые теги; дальше эти категории наполняет заказчик через редактор. Пока элементов меньше, чем нужно на 15 игроков, валидатор показывает предупреждение.

## Этап 6. Расширяемость

1. Редактор контента: паки, характеристики, элементы, веса, вкл/выкл, теги, способности с конструктором эффектов, предпросмотр карточки.
2. Валидатор совместимости.
3. Импорт/экспорт паков в JSON, комбинирование паков, приоритеты.
4. Кастомная игра: ведущий вписывает характеристики вручную.
5. `docs/CONTENT_GUIDE.md`: как добавить профессию, болезнь, характеристику, новый эффект.

## Этап 7. Тестирование

1. Vitest: все ветки голосования, таблицы, генерация с ограничениями, каждый эффект, проекции.
2. Интеграция: 6 и 15 одновременных сокет-клиентов, одинаковые результаты у всех, гонки действий.
3. Переподключение: обновление страницы посреди фаз и голосования, перезапуск сервера посреди партии.
4. Безопасность: ни одна проекция и ни один ответ API не содержит закрытых чужих значений.
5. E2E (Playwright): полная партия на 6 игроков в нескольких браузерных контекстах; мобильная ширина.
6. Проверка через туннель: подключение с телефона по мобильному интернету и с другого ПК, партия на 15 человек с разных устройств.
